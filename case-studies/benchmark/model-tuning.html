AI lead scoring, ongoing optimization

A model that keeps learning

Real results from Benchmark's CRM flow back into the lead scoring model, so its conversion predictions get sharper over time and fit the care each community offers.

The feedback loop

Calibrate once, then keep tuning

The first calibration uses Benchmark's historical won and lost leads. After launch, every inquiry that reaches a final outcome becomes new evidence. The loop compares what the model predicted with what actually happened, then tunes the existing variables and considers adding or removing variables.

Model Controls keeps the settings visible and understandable, and lets the team apply small manual tweaks to specific variables. Overall, though, this is a model that can be automated: a scheduled AI process, weekly or monthly, pulls recent CRM results and continuously tunes the model.

How each cycle works

01

Pull finalized CRM outcomes

Each cycle pulls leads that have reached a final outcome, won (deposit or move-in) or lost (with lost-lead reason), along with the answers, signals and predictions recorded when each lead was scored.

02

Split into training and test groups

Finalized leads are divided into a training group used to adjust the model and a held-out test group used only to check whether the adjusted model predicts better.

03

Compare predicted vs. actual conversion

For every variable, compare the model's predicted conversion rate with what actually happened. Which answers moved conversion more, or less, than their current points and weights assume?

04

Tune weights and variables

Adjust answer points and weights where predictions and outcomes diverge. Flag variables that add little predictive value for removal, and propose new variables when patterns in the CRM data point to a signal the model does not yet capture.

05

Validate, review, then publish

The tuned model must beat the current model on the test group before it goes live. A marketing owner reviews the proposed changes in Model Controls, approves them, and the new version starts scoring the next inquiries.

Automated, visible, and local

Scheduled AI tuning

An AI agent runs the cycle on a weekly or monthly schedule: it pulls recent CRM outcomes, runs the comparison, drafts the proposed changes with the evidence behind each one, and queues them for review. No one has to remember to recalibrate.

Model Controls stay in the loop

Every setting the agent changes is shown in Model Controls, with the before and after values. The team can see why the model scores the way it does, apply small manual tweaks to specific variables, and keep or roll back a change.

Tuned for each community

The same agent can tune a model for each location, so conversion predictions match the care that community offers, its local pricing and distance buckets, and the outcomes its own leads produce. A community without memory care, for example, is not tuned on memory care conversions.

Enough data before a change

Communities with few finalized leads keep the shared model until they have enough outcomes to tune reliably; the minimum sample size is set with Benchmark.

Fair housing checks every cycle

Care needs set care level only, not lead priority. Each cycle checks that tuning has not shifted priority onto care needs or protected-class proxies before a change can be approved.

What Benchmark provides

CRM access to finalized outcomes (deposit, move-in, lost reason) by community and lead source, and a named owner who approves model changes.
